# 万能下载管理器开发计划

本文档用于跟踪万能下载管理器桌面应用开发进度。当前项目采用 Tauri + React + TypeScript + Rust + aria2 技术栈，目标是先完成类似 IDM 的核心下载管理能力，再逐步扩展浏览器接管、媒体解析和站点规则。

## 总体开发顺序

```text
需求与设计定稿
  -> 桌面工程基线
  -> 980px 三栏主界面
  -> 内置 aria2 引擎与 RPC 基础
  -> 下载任务创建与列表管理
  -> 多线程下载与断点续传
  -> 任务持久化与应用重启恢复
  -> 文件操作与任务删除策略
  -> 错误处理与状态提示
  -> 响应式与窗口伸缩验证
  -> 打包、联调与发布准备
```

## 本次计划审查结论

当前最重要的边界是先做“可用的桌面下载管理器”，而不是一次性复刻完整 IDM。第一版必须把普通 HTTP/HTTPS 链接下载、多线程、断点续传、任务列表管理、应用重启恢复做稳。

UI 已定为默认 980px 宽版三栏布局：左侧分类、中间任务列表、右侧详情常驻。开发时需要始终保护中间任务列表的可用宽度，不能为了细节面板让列表被挤坏。

下载核心依赖内置 aria2。Rust 后端不重复实现下载协议，而是负责随软件打包 aria2、启动内置 aria2 进程、RPC 调用、任务状态归一化和本地任务元数据持久化。第一版不要求用户单独安装 aria2。

## 目录结构约定

第一版采用前后端同仓结构：

```text
.
├── docs
│   ├── development-plan.md
│   └── superpowers/specs
├── src
│   ├── api              前端调用 Tauri 命令的封装
│   ├── components       下载器界面组件
│   ├── state            前端任务状态、筛选、选中项
│   ├── styles           全局样式和响应式布局
│   └── utils            格式化速度、大小、时间等工具
├── src-tauri
│   ├── src
│   │   ├── aria2        内置 aria2 二进制定位、RPC 客户端和进程管理
│   │   ├── commands     暴露给前端的 Tauri 命令
│   │   ├── models       下载任务、配置、状态模型
│   │   ├── services     下载任务业务编排
│   │   └── store        本地任务持久化
│   └── tauri.conf.json
└── package.json
```

目录可以在实际脚手架生成后微调，但职责边界保持不变：前端只负责交互和展示，Rust 后端负责内置 aria2、文件系统和任务持久化。

## 第三阶段：内置 aria2 引擎与 RPC 基础

目标：Rust 后端能够定位、启动和管理随软件打包的 aria2 进程，并通过 JSON-RPC 查询 aria2 状态。

状态：已完成第一版。

计划能力：

- 将 aria2 二进制作为应用资源随软件打包。
- 启动内置 aria2 RPC 服务。
- 维护 aria2 RPC 地址、端口和 secret。
- 查询 aria2 版本和全局状态。
- 在 UI 底部显示 aria2 已连接或连接失败。

验收标准：

- [x] 应用启动后优先使用内置 aria2。
- [x] 内置 aria2 二进制缺失或启动失败时后端返回明确错误。
- [x] Rust 后端可以成功调用 aria2 JSON-RPC。
- [x] 前端能显示 aria2 引擎状态。
- [ ] 退出应用时不会留下异常僵尸进程。
- [ ] 打包产物包含目标平台对应的 aria2 二进制。

实现说明：

- 第一版优先支持内置 aria2，不要求用户安装 aria2 或配置 PATH。
- Windows 第一版内置 `aria2c.exe`；后续支持 macOS/Linux 时，分别打包对应平台二进制。
- aria2 RPC 失败不能导致整个桌面应用崩溃。

## 第五阶段：多线程下载与断点续传

目标：让下载任务具备 IDM 类下载器最核心的多连接加速和断点续传能力。

状态：基础已接入。

计划能力：

- 创建任务时设置 aria2 `split`。
- 创建任务时设置 `max-connection-per-server`。
- 创建任务时设置 `min-split-size`。
- 创建任务时启用 `continue=true`。
- 暂停后继续下载时保留已有进度。
- 对不支持 Range 的服务器显示“不支持断点续传”。

验收标准：

- [x] 默认任务使用配置中的线程数。
- [ ] 单任务可以调整线程数。
- [ ] 暂停任务后继续，已下载进度不会从 0 开始。
- [x] aria2 启动参数保留 session 和续传配置。
- [ ] 不支持断点续传的任务有明确状态提示。
- [ ] 网络中断后重试优先尝试续传。

实现说明：

- aria2 是实际下载引擎，应用不自行实现 HTTP 分片下载。
- 断点续传能力依赖服务器 Range 支持，UI 必须诚实展示限制。

验收标准：

- [x] 应用重启后仍能读取本地历史任务。
- [ ] 未完成任务可以继续下载。

- [x] 任务元数据损坏时后端返回明确错误。
