# 万能下载管理器设计文档

日期：2026-05-31

## 目标

开发一个类似 IDM 的桌面下载管理器。第一版聚焦“输入链接即可下载、任务列表可管理、多线程下载、断点续传、aria2 后端驱动”，先做稳定可用的核心体验，再扩展浏览器接管、站点规则和复杂媒体解析。

## 技术方向

确定使用 Tauri + React + TypeScript + Rust + aria2。

Tauri 负责桌面窗口、系统能力和 Rust 后端命令；React 负责 UI；Rust 端负责启动和管理随软件内置的 aria2 进程、调用 aria2 RPC、维护任务状态；aria2 负责多连接下载、分片下载、断点续传和任务恢复。

备选方案曾考虑 Electron + aria2 和本地 Web 控制台，但第一版确定采用 Tauri/Rust 路线，更适合长期演进为轻量桌面下载器。

## MVP 功能

第一版必须包含：

- 输入 HTTP/HTTPS 链接创建下载任务。
- 支持 aria2 多线程/多连接下载。
- 支持断点续传：暂停后继续、应用重启后恢复未完成任务。
- 任务列表展示文件名、来源、进度、速度、剩余时间、状态和快捷操作。
- 支持暂停、继续、删除、重试、打开文件、打开目录。
- 支持默认下载目录、单任务目录、默认线程数和单任务线程数。
- 显示 aria2 连接状态、全局速度、活跃任务数、磁盘剩余空间。

第一版暂缓：

- 浏览器自动嗅探和接管下载。
- BT、磁力链、复杂媒体解析。
- 登录站点 Cookie 规则库。
- 完整 IDM 级别的站点兼容。

## UI 布局

采用用户确认的 980px 宽版三栏布局。

默认窗口约 980×680，最小常规窗口约 900×600。布局保留三栏：

- 左侧分类栏：150px，展示全部、下载中、等待、完成、失败，以及类型筛选。
- 中间任务列表：`minmax(430px, 1fr)`，是主工作区。
- 右侧详情栏：270px，常驻展示选中任务详情、进度、保存目录、连接数、线程数、限速和操作按钮。

顶部工具栏常驻，包含应用名、链接输入框、新建、开始、暂停和总速。底部状态栏展示 aria2 状态、默认线程数、下载目录和磁盘剩余。

## 响应式规则

布局必须弹性、可伸缩，窗口变化时不能乱。

- 三栏默认列宽：`150px minmax(430px, 1fr) 270px`。
- 窗口放大时优先增加中间任务列表宽度。
- 低于 900px 时右侧详情折叠为 drawer。
- 低于 820px 时左侧分类折叠为顶部筛选。
- 所有 grid/flex 子项设置 `min-width: 0`，长文件名、URL、错误信息使用 ellipsis。
- 列表行使用 CSS Grid，不使用绝对定位排版。
- 小宽度下按钮可切换为 icon button，避免文字换行挤压。
- 禁止内容撑破容器导致横向滚动。

## 下载核心

aria2 作为软件内置下载引擎随应用打包发布，不要求用户单独安装。运行时由 Tauri 后端从应用资源目录定位 aria2 二进制，启动为本地后台进程，并负责停止、健康检查和 RPC 通信。应用使用 aria2 JSON-RPC 创建下载任务、暂停任务、继续任务、删除任务、查询状态。

多线程下载通过 aria2 参数控制：

- `split`：分片数量。
- `max-connection-per-server`：单服务器最大连接数。
- `min-split-size`：最小分片大小。
- `continue=true`：启用断点续传。

断点续传策略：

- 未完成任务保留 `.aria2` 控制文件。
- 应用退出前保存任务元数据，包括 URL、保存目录、文件名、aria2 gid、状态、线程配置。
- 应用启动后恢复未完成任务，并重新绑定 aria2 gid。
- 如果远端服务器不支持 Range 请求，UI 明确提示“不支持断点续传”，但仍允许普通下载。
- 删除任务时区分“仅移除任务”和“移除并删除文件”。

内置 aria2 打包策略：

- Windows 第一版内置 `aria2c.exe`，放入 Tauri 资源目录并随安装包发布。
- Rust 后端优先使用内置 aria2，不依赖系统 PATH。
- 若内置 aria2 启动失败，UI 显示“内置下载引擎启动失败”，不要求用户手动安装 aria2。
- 后续支持 macOS/Linux 时，为不同平台分别打包对应 aria2 二进制。

## 数据模型

核心任务字段：

- `id`：应用内部任务 ID。
- `gid`：aria2 任务 ID。
- `url`：下载 URL。
- `fileName`：文件名。
- `saveDir`：保存目录。
- `totalBytes`、`completedBytes`、`downloadSpeed`、`connections`。
- `status`：waiting、active、paused、complete、error、removed。
- `resumable`：是否支持断点续传。
- `createdAt`、`updatedAt`。
- `options`：线程数、限速、请求头等。

任务元数据可以先存本地 JSON 或 SQLite。第一版如果任务关系简单，JSON 足够；如果要更稳妥地支持历史、筛选和恢复，优先 SQLite。

## 错误处理

常见错误必须在 UI 可见：

- 内置 aria2 二进制缺失、启动失败或 RPC 连接失败。
- URL 无效。
- 保存目录无权限或不存在。
- 磁盘空间不足。
- 网络超时、DNS 失败、服务器 403/404/5xx。
- 服务器不支持断点续传。
- 文件已存在导致命名冲突。

错误任务支持重试。重试时保留已下载文件和 `.aria2` 控制文件，优先续传。

## 测试与验证

实现阶段需要覆盖：

- 下载任务创建参数正确传给 aria2。
- 暂停后继续时保留已下载进度。
- 应用重启后恢复未完成任务。
- 不支持 Range 的链接能给出明确提示。
- 任务列表在 980px、900px、820px 三个宽度下不溢出、不遮挡。
- 删除任务时“仅移除”和“删除文件”行为分离。

UI 验证需要使用浏览器/桌面窗口截图检查默认尺寸和断点尺寸，确认三栏、drawer、顶部筛选切换正常。
